# Четыре экземпляра Revit 2026

Сборка: `2026.10.09-multi-instance.8`.

## Автоматический запуск

Cortex запускает сервер один раз при первом событии Idling, когда доступен UIApplication.
Открытый проект не требуется. Успешный запуск меняет значок на зелёный без окна OK.
Ручное выключение сохраняется до ручного включения или перезапуска Revit.
Если запуск не удался, Cortex записывает исключение в локальный журнал и показывает одно неблокирующее уведомление.
Повторных попыток на каждом Idling нет. Для повторной попытки используйте Cortex Switch.

| Профиль | Порядок автоматического выбора |
|---|---|
| Release | 8080 → 8888 → 8880 → 8088 |
| Dev | 8081 → 8889 → 8083 → 8891 |

Порт назначается при привязке TCP-сокета. Одновременные запуски не могут занять один порт.
Порядок назначения зависит от готовности Cortex, а не от номера окна или имени проекта.
Занятый посторонней программой порт недоступен Cortex. Если все четыре заняты, запуск завершается ошибкой.
После назначения порт закреплён за процессом. Выключение освобождает сокет, но не меняет закреплённый порт.
Если его занял другой процесс, повторное включение выдаёт ошибку без перехода на другой порт.

## Подключения агентов

Создайте отдельные записи MCP: `revitcortex_8080`, `revitcortex_8888`, `revitcortex_8880`, `revitcortex_8088`.
Все записи запускают один установленный `RevitCortex.Server.exe`, но каждая задаёт свой `REVITCORTEX_PORT`.
Пример конфигурации: [mcp-four-revit.json](../distribution/config-templates/mcp-four-revit.json).
Замените путь пользователя перед применением. Публикация кода не изменяет установленную конфигурацию клиентов.

При подключении сервер объявляет свой фиксированный порт в имени и начальных инструкциях MCP.
Пользовательский запрос «работай на порту 8888» означает именно это подключение.
Ошибка подключения не разрешает переход на другой порт.

- `get_connection_status`: порт, PID, instanceId, название/путь документа, generation, isServiceDocument и build. Работает без документа.
- `list_revit_instances`: проверяет четыре Release-порта, четыре Dev-порта и порт текущего подключения. Можно передать до 16 портов явно.
- `get_project_info`: проверяет текущий документ через поток Revit и возвращает его метаданные вместе с идентификацией подключения.
- `say_hello`: проверяет цель через поток Revit, в том числе без документа.

Статус и обнаружение читают только сохранённые примитивные данные. Они не обращаются к API Revit из сетевого потока.
Поле `snapshotOnly=true` и время `snapshotUpdatedUtc` показывают, что это снимок состояния.
Доступный TCP-сервер не доказывает, что интерфейс Revit отвечает. Зависший API-вызов может оставить старый снимок.
Обнаружение выполняется параллельно с ограничением ожидания около 1,5 секунды на порт. Оно не меняет выбранное подключение.

## Защита выбранной цели

MCP запоминает instanceId, порт и поколение документа после проверки или первого запроса состояния перед командой.
Перед последующими командами сервер сравнивает эту цель с текущим состоянием.
Плагин повторяет проверку при маршрутизации и перед выполнением ExternalEvent.
После окна подтверждения контекст проверяется ещё раз.
При несовпадении команда отклоняется. Автоматического повтора нет.
После намеренного переключения проекта вызовите `get_project_info` или `say_hello`, проверьте результат и только затем продолжайте.
Эти два явных запроса обновляют привязку. Простой просмотр списка экземпляров её не меняет.

Порт не является постоянным идентификатором проекта. При перезапуске его может занять другой Revit.
Новому процессу соответствует новый instanceId, даже если Windows повторно использовала PID.
Защита не определяет смысл пользовательского запроса: агент всё равно обязан сопоставить название и путь проекта.

## Пустой Revit и семейства

Первый `send_code_to_revit` без активного документа подготавливает служебный проект отдельным запросом, затем запускает скрипт один раз.
Сначала проверяются разрешение C#, отключение инструмента, sandbox и режим транзакции. Режим «только чтение» блокирует подготовку.
`ensure_service_document` можно вызвать отдельно. Он не заменяет уже активный проект.
В автоматическом сценарии появление другого активного документа во время подготовки вызывает отказ.
Служебный проект создаётся без шаблона в метрических единицах. Поэтому настройки, виды и содержимое рабочего шаблона в нём отсутствуют.
Он сохраняется по уникальному пути `.revitcortex/service-projects/<instanceId>/Cortex-service-<PID>-<GUID>.rvt` и открывается через API.
Каждый процесс получает собственный файл. Перезапись и автоматическое удаление служебных проектов отсутствуют.
Скрипт может открыть `.rfa` в фоне, изменить, сохранить и закрыть его. Пустой проект остаётся открытым для работы Cortex.
Для известного рабочего проекта агент обязан найти именно его, а не создавать замену.

Сохранение служебного RVT не является частью транзакции пользовательского скрипта.
При ошибке следующего этапа файл может остаться; ответ сообщает путь. При таймауте проверяйте состояние до повторного запроса.
Создание и активацию требуется проверить в живом Revit 2026. Нативные сбои и все возможные окна API не перехватываются.

## Подтверждения и общие файлы

Обычные и критические подтверждения имеют независимые галочки, включённые при запуске Revit.
Каждый запрос сохраняет видимый отсчёт три секунды. Снятие галочки действует только в этом процессе.
No/X/Escape отменяют запрос. Sandbox, аудит, разрешение выполнения C# и режим «только чтение» сохраняются.
Временные скрипты хранятся в отдельных каталогах запуска процесса. Закрытие одного Revit не удаляет скрипты другого.
Общие настройки не редактируйте одновременно из нескольких экземпляров. Power BI по-прежнему использует один callback-порт 27016.

## Явный порт запуска

`start-revit-instance.ps1 -Port 8880` остаётся дополнительным способом закрепить роль процесса.
Переменная задаётся только дочернему процессу. Не используйте глобальный setx.
Неверное значение переменной в плагине вызывает предупреждение и возврат к автоматическому списку.
MCP-сервер при неверном значении завершается с ошибкой. Старый Port в общих settings.json не используется.

Перед установкой обновите Plugin/Core/Tools и MCP-сервер вместе. Обновите навыки отдельно и переподключите клиентов.
Проверки в Revit перечислены в [документе для Claude](multi-instance-claude-review.md).
