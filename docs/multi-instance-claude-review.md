# Проверка четырёх экземпляров Revit и запуска без документа

Дата: 2026-10-09. Сборка: `2026.10.09-multi-instance.8`.
Ветка: `fix/per-instance-revit-port`. PR: [#2](https://github.com/AlexFspb/RevitCortex/pull/2).
База этого изменения: `d4524ee9b64a2e69503b9adbf9b3510c421efc1d`.

## Согласованное поведение

- Release автоматически выбирает первый свободный порт: 8080, 8888, 8880, 8088.
- Dev использует отдельные порты: 8081, 8889, 8083, 8891.
- Сервер запускается один раз при первом Idling. Открытый документ не нужен.
- Ручная остановка сохраняется до ручного запуска или перезапуска Revit. Окон OK при переключении нет.
- Обычные операции сохраняют включённое автовыполнение и отсчёт 3 секунды.
- Для C# флажок автовыполнения теперь тоже включён при каждом запуске Revit. Остаются Yes, No, отмена и видимый отсчёт 3 секунды.
- Пользователь может снять флажок. Выбор действует внутри процесса и не записывается в настройки.
- Песочница, режим чтения, отключённые инструменты, EnableCodeExecution, журналирование и прежние проверки семейства сохраняются.

## Изменения для проверки по коду

### Порты и идентификация

`CortexPort.AutomaticPorts` возвращает четыре порта для каждого профиля. Явный REVITCORTEX_PORT остаётся фиксированным. Занятый назначенный порт не вызывает переход на другой порт при повторном запуске слушателя.

MCP сообщает настроенный порт уже в initialize: имя сервера `RevitCortex-<port>` и инструкции. `get_connection_status` возвращает сохранённые примитивные данные: PID, порт, instanceId, поколение документа, название, путь, признак служебного проекта, время снимка, buildId и MVID. Он не вызывает Revit API из потока сокета. Отключение инструмента в настройках учитывается до быстрого ответа.

`list_revit_instances` проверяет известные порты параллельно с ограничением времени. Можно передать до 16 портов. Инструмент не меняет соединение. `get_project_info` и `say_hello` возвращают идентичность и явно обновляют выбранный контекст.

`RevitConnectionManager` закрепляет идентичность процесса и поколение документа. При несовпадении обычный запрос отклоняется до отправки команды. Сервер добавляет `_cortexExpected`. Плагин повторно проверяет контекст перед выполнением и после подтверждения. Перезапуск Revit на прежнем порту не считается прежним экземпляром.

Это защита от устаревшего контекста, а не авторизация TCP-клиента. Старые внутренние вызовы без `_cortexExpected` сохраняют прежний контракт. На первом запросе клиент может закрепить текущий контекст. Совпадение с проектом, названным пользователем, агент должен проверить сам. Нельзя автоматически заменять отсутствующий рабочий проект служебным.

### Пустой Revit и служебный проект

`StartupAttempt` разрешает единственную попытку запуска. При ошибке Cortex сохраняет полное исключение в локальный startup-PID.log и показывает одно немодальное уведомление. Повторная попытка доступна через Cortex Switch.

Новый `ensure_service_document` выполняется через ExternalEvent. Если документ уже активен, явный вызов возвращает его состояние без переключения. Автоматическая подготовка требует, чтобы Revit оставался пустым; появление активного проекта отклоняет запрос.

При первом `send_code_to_revit` без документа MCP сначала вызывает подготовку. Инструмент проверяет EnableCodeExecution, отключение C#, режим транзакции и песочницу. Режим чтения и отключение самого инструмента проверяет маршрутизатор. Затем Cortex создаёт метрический проект, сохраняет его под уникальным именем и закрывает фоновый документ. После проверки результата Close(false) Cortex открывает этот файл через OpenAndActivateDocument. Файл находится в `.revitcortex/service-projects/<instanceId>/`.

После подготовки MCP закрепляет новое поколение документа и отправляет скрипт один раз. При ошибке подготовки скрипт не отправляется. Запросы состояния и чтения сами проект не создают. Это вспомогательный проект для существующего механизма C#, а не новый универсальный редактор семейств.

Подготовка предшествует полной компиляции и подтверждению C#. Поэтому служебный RVT может остаться после ошибки компиляции или отмены скрипта. Ответ содержит serviceProjectPrepared/serviceProjectPath; ошибка подготовки содержит scriptExecuted=false. Cortex не удаляет эти файлы и не закрывает активный проект автоматически. Ошибки закрытия фонового документа записываются отдельно.

### Независимость процессов

Временные скрипты перенесены в каталог процесса с GUID запуска. Имена скриптов тоже содержат GUID. Завершение одного Revit удаляет только его временные скрипты. Старые файлы в общем каталоге не удаляются этой очисткой.

Настройки всё ещё общие. Их нельзя одновременно редактировать из нескольких Revit. Power BI callback на порту 27016 остаётся отдельным ограничением. Четыре Revit также требуют больше памяти. Эти изменения не предотвращают нативные сбои API, зависшие нативные вызовы и все возможные модальные окна.

## Обязательная проверка в Revit 2026

1. Запустить четыре Revit без проектов. Проверить зелёный индикатор и четыре разных Release-порта.
2. Проверить PID, порт, название и путь через отдельные MCP-подключения. Проверить различие процессов в списке экземпляров.
3. Остановить один сервер. Убедиться, что следующий Idling его не включает. Запустить вручную на прежнем порту.
4. Проверить исчерпание портов и Dev-профиль. Проверить отсутствие окон OK при запуске и остановке.
5. В пустом Revit запросить состояние. Убедиться, что проект не создан.
6. Отправить небольшой C#-запрос в пустой Revit. Проверить создание и открытие служебного RVT, путь ответа и выполнение ровно один раз.
7. Проверить отказ подготовки при отключённом C#, отключённом инструменте, режиме чтения и ошибке песочницы.
8. Проверить ошибку компиляции и отмену после подготовки. Скрипт не должен выполняться; созданный служебный проект может остаться.
9. Открыть обычный проект между проверкой состояния и выполнением. Проверить отказ устаревшего запроса без изменения нового проекта.
10. Переключить документ и перезапустить процесс на прежнем порту. Проверить отказ до явного get_project_info или say_hello.
11. Проверить включённый флажок C#, видимые 3 секунды, отмену, снятие флажка и повторный запуск Revit. Повторить для обычных операций.
12. Закрыть фоновое семейство и один из Revit. Проверить соединения остальных процессов и сохранность их временных скриптов.
13. Повторить проверки EditFamily, результата скрипта, отказов транзакций и таймаутов из предыдущего отчёта.

## Основания Autodesk и границы проверки

Создание проекта использует [Application API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/94db8ea8-d2c3-5e71-8030-466bcb8e4426.htm). Активация использует [OpenAndActivateDocument](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/3b3d671d-47ec-2ed8-1818-a7c19d01884b.htm).

Справочник метода содержит ограничения контекста событий. [Официальное пояснение Autodesk об ExternalEvent](https://blog.autodesk.io/idling-enhancements-and-external-events/) описывает допустимое применение при соблюдении условий документа и транзакций. Здесь подготовка запускается через ExternalEvent без активного документа и без собственной открытой транзакции. Это основание реализации, но не замена проверке в установленном Revit 2026.

Фоновое открытие семейства через [OpenDocumentFile](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/14826965-b83e-110c-1466-cc7667def9c8.htm) не создаёт видимой вкладки. Правила [EditFamily](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/56e636ee-5008-0ee5-9d6c-5f622dedfbcb.htm) и прежние механические проверки сохраняются.

Документация для оператора: [несколько экземпляров](MULTIPLE_REVIT_INSTANCES.md), [редактирование семейств](family-editing.md). Пример четырёх подключений: [mcp-four-revit.json](../distribution/config-templates/mcp-four-revit.json). Проверять следует непосредственно эту ветку GitHub; архив не требуется.
