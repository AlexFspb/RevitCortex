# Индикация всех обращений к Cortex

Дата: 26.10.2026. Сборка: `2026.10.26-request-activity.12`.
База: `e3e4f55b8c0391da95c046221328334e60cbed66`. Ветка: `fix/per-instance-revit-port`, PR №2.

## Запрос пользователя

Показывать обращения агентов к конкретному экземпляру Cortex, включая обычные проверки подключения.
Пользователь наблюдает значок в панели быстрого доступа Revit. Частые вспышки допустимы.

## Причина изменения

Раньше индикация начиналась только внутри ExternalEvent. Проверки состояния не включали её.
Короткая команда могла вернуть зелёный цвет до того, как Revit успевал перерисовать значок.
Причина поведения панели быстрого доступа в конкретном сеансе не доказана: экран и интерфейс не исследовались.

## Новое поведение

- SocketService сообщает о каждой полученной строке запроса до маршрутизации.
- Проверки get_connection_status, say_hello, ответы из кэша, отказы и неверные JSON-запросы включают индикацию.
- Оранжевый означает запрос C#, синий — остальные запросы. Проверка состояния больше не исключается.
- Изменение интерфейса выполняется через UI Dispatcher. Сетевой поток не меняет интерфейс и не ждёт перерисовки.
- При занятом Revit уведомления объединяются: хранится последнее уведомление и максимум один ожидающий вызов Dispatcher.
- Короткое обращение оставляет вспышку на 1,2 секунды с момента обработки уведомления интерфейсом.
- Яркость чередуется каждые 300 мс, пока интерфейс может обрабатывать события.
- Выполняющаяся команда имеет приоритет над фоновыми проверками. Таймаут клиента не снимает её состояние выполнения.
- После завершения обработчика остаётся вспышка недавней активности. Подсказка отличает её от выполнения.
- Остановленный сервер отображается серым. Ошибка индикации не должна прерывать обработку запроса.

Это индикатор входящего обмена. Он не означает, что Cortex сам инициировал обращение к агенту.
Частые запросы могут сливаться в одну продолжительную индикацию. Отдельная вспышка на каждый пакет не гарантируется.
Пустое TCP-соединение без строки запроса не включает индикацию. Локальные MCP initialize/tools/list без TCP-запроса также её не включают.
Поиск экземпляров может обратиться к нескольким Revit; тогда каждый получивший запрос экземпляр покажет активность.

## Ограничения

Revit может задержать перерисовку, когда его главный поток занят. Мгновенная смена цвета и непрерывное мигание не гарантируются.
После длинной синхронной команды сохраняется вспышка, чтобы изменение не исчезло сразу при завершении.
Отображение на панели быстрого доступа требует проверки в работающем Revit.
Код не вызывает DoEvents, не создаёт вложенный цикл сообщений, не меняет фокус и не задерживает выполнение команды ради анимации.
Настройки портов, автовыполнения, защита скриптов и обработка транзакций не изменены.

## Проверка

- Полный набор Debug R26: 790 passed, 1 skipped, 0 failed, всего 791.
- Plugin/Tools Debug собраны вместе с тестами. Plugin/Tools Release R26 и Server Release собраны без ошибок.
- Остались прежние предупреждения Power BI, UpdateChecker и анализатора тестов.
- Пропущен прежний тест нативного ExternalEvent: TryPrepareExecution_RejectsSecondCommandUntilFirstExternalEventDrains.
- Тесты с управляемыми часами проверяют короткие запросы, задержку UI, удержание цвета, приоритет скрипта и завершение индикации.
- Проверены 10 000 уведомлений с фонового потока, объединение обновлений, ошибка отображения и уведомление после Dispose.
- Реальные TCP-тесты проверяют уведомления для status/hello/неизвестного метода/неверного JSON и сохранение ответов при ошибке наблюдателя.
- Тесты не показывают окна и не отправляют команды работающему Revit.

## Проверка после установки

1. Вызовите get_connection_status на выбранном порту. Проверьте синюю вспышку на ленте и панели быстрого доступа.
2. Повторите проверку say_hello и быстрым чтением проекта. Зелёный цвет должен возвращаться после периода недавней активности.
3. Выполните безопасный C#-запрос. Проверьте оранжевую индикацию, в том числе после завершения.
4. Во время длительного скрипта выполните проверку состояния. Она не должна сбросить оранжевую индикацию в зелёную.
5. Сверьте подпись подсказки: «Выполняется» во время выполнения и «Индикатор недавней активности» после завершения.
6. Проверьте второй экземпляр Revit. Только получивший запрос экземпляр должен показать активность.

Сборка требует отдельной установки при закрытых экземплярах Revit. Проверяйте исходники напрямую в GitHub; архив для ревью не нужен.
