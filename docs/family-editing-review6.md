## Изменения по семи замечаниям

1. Проверка компилятора выполняется перед подтверждением и сохранением скрипта.
   Cortex использует семантическую модель вместо предварительного поиска имени.
   Это исключает ложный отказ для пользовательского метода `EditFamily`.
   `TryPrepare` возвращает проверенную сборку и режим. `ExecutePrepared` использует их без повторной компиляции.
   После подтверждения состояние документа проверяется снова. Перед исполнением проверка повторяется.
2. Параметр `strictWarnings` доступен через MCP и плагин. По умолчанию он равен `false`.
   В `auto` значение `true` передаётся в `Configure(tx, rollbackOnWarnings: true)` до изменений.
   Ошибки вызывают откат при обоих значениях. Предупреждения вызывают откат только в строгом режиме.
   В `none`/`group` значение `true` отклоняется с `InvalidInput` до подтверждения.
   Там скрипт обязан настроить каждую собственную транзакцию. Это ограничение исключает ложное обещание защиты.
3. В режиме `none` компилятор не переписывает неразрешённый вызов из `CandidateSymbols`.
   Ошибка аргумента остаётся связана с исходным методом и номером аргумента.
   В `auto`/`group` распознанный кандидат также получает сообщение о неверном режиме.
4. Ответ содержит ошибки защиты и обычные ошибки компиляции одновременно.
   При ошибках защиты компилятор проверяет исходное дерево. Даже успешный `Emit` не возвращает исполняемые байты.
5. Тесты используют настоящие `WrapCode` и `PrefixLines`.
   Они проверяют строки 1 и 3 для ошибок компиляции и запретов защиты.
6. Ответ отличает строгий откат из-за предупреждений от ошибки Revit.
   Контекст содержит `rollbackOnWarnings`, `hasErrors`, `warningCount`, описания и ID элементов.
   Неподтверждённый откат не объявляется успешным. Формирование ответа проверяется в Core без Revit API.
7. Устаревший `#if REVIT2025_OR_GREATER` удалён из рабочего компилятора.
   Компилятор и обработчик вызовов теперь одинаково доступны в единственной поддерживаемой конфигурации Revit 2026.

## Уточнения после повторной проверки Claude

База этих уточнений: `fe4ce8b2b9aebd57e88e8339e96c78966f3ce461`.
Повторный отчёт подтвердил исправление всех семи замечаний. Новых ошибок проверка не выявила.

- Из условия `ScriptTransactionMode.Validate` удалены избыточные сравнения. Поведение сохранено.
- Описания MCP, плагина и документация явно указывают условия сохранения скрипта.
  При отказе компилятора или защиты файл не создаётся даже с `reusable: true`. Поле `scriptPath` отсутствует.
- Руководство описывает возможную задержку первого запроса до подтверждения или отказа.
  Причина — загрузка компилятора и компиляция. Отсчёт подтверждения начинается после этого этапа.
- Комментарий к публичному `RoslynExecutor.Execute` объясняет его сохранение для существующих вызывающих компонентов.
  MCP использует `TryPrepare` и `ExecutePrepared`.

## Совместимость

Порты 8080/8888, отдельные порты Dev, подтверждения и трёхсекундные отсчёты не изменены.
`Configure(tx)` сохраняет прежнее поведение. Строгая обработка включается явно согласно условиям задачи.
Sandbox, аудит, режим «только чтение» и проверка контекста остаются обязательными.
Существующие ограничения нативных сбоев, внешних эффектов и таймаутов сохраняются.
Предыдущие изменения и файлы в режиме `none` не получают общего отката.

## Проверки в Revit

На копии проекта выполните следующие проверки перед рабочей установкой:

1. Отправьте `EditFamily` с `auto` и `group`. Проверьте отказ без окна подтверждения и без сохранения скрипта.
   При первом запросе возможна задержка загрузки компилятора. Это также относится к ответу об отказе.
2. Выполните допустимый скрипт с `none`. Проверьте одно подтверждение и успешный прямой вызов.
3. Проверьте повторный контроль документа после подтверждения и блокировку вызова при открытой транзакции.
4. Вызовите известное предупреждение на одном элементе с `auto`, сначала с `strictWarnings=false`, затем с `true`.
5. Проверьте сохранение изменений и список предупреждений в первом случае. Проверьте откат и явную причину во втором.
6. Проверьте откат при ошибке Revit для обоих значений. Диалог сбоев не должен ждать пользователя.
7. В `none`/`group` настройте строгий обработчик каждой транзакции. Верните примитивные данные диагностики.
8. Повторите прежние проверки загрузки и закрытия семейства, двух экземпляров Revit и сохранения соединения.

Автоматические тесты используют API-замены. Они не доказывают отсутствие нативных сбоев и всех модальных окон.
