# Балки и колонны: чтение и создание

Обновлено: 4 ноября 2026 года. Целевая платформа: Revit 2026 / .NET 8.
Сборка исходников: `2026.11.04-review-fixes.17`.

## Назначение

`get_location_curves` читает расположение балок и несущих колонн.
`author_structural_members` создаёт прямые балки и вертикальные несущие колонны из уже загруженных семейств.
Инструменты дополняют существующее создание балочной системы и восстановление конструкций из IFC.
Они не рассчитывают несущую способность и не подтверждают пригодность сечения.

Источник идеи и исходной реализации: [woodhouse711/RevitCortex, commit 6468c91](https://github.com/woodhouse711/RevitCortex/commit/6468c9191e00871a53a233282907a1ea7adb909f).
В этой версии изменены обработка ошибок, ограничения ответа и порядок отката.
Исходная лицензия MIT и уведомления в `LICENSE` сохраняются.

## Подключение и единицы

Используйте указанный пользователем порт. Сначала проверьте документ через `get_project_info`.
Оба инструмента используют обычную проверку контекста Cortex и существующий `ExternalEvent`.
Изменение документа или процесса блокирует дальнейшую команду до повторной проверки.

Поля `p0_ft` и `p1_ft` задают координаты во внутренних футах Revit.
Для длины: `футы = миллиметры / 304.8`.
Для передачи координат из `get_location_curves` в `create_pipe` или `create_duct` умножьте их на 304,8.
Числовые значения параметров также используют внутренние единицы Revit.
Угол, площадь и объём имеют другие единицы. Не преобразуйте все числа как длину.
Названия семейств, типов и параметров нужно предварительно прочитать из модели.

## Чтение

Аргументы `get_location_curves`:

| Аргумент | Значение |
|---|---|
| `categories` | `StructuralFraming`, `StructuralColumns`; по умолчанию обе категории |
| `elementIds` | Необязательный список, максимум 5000 ID; пустой список означает пустой запрос |
| `includeTypeParams` | По умолчанию `false` |
| `offset` | По умолчанию `0` |
| `limit` | От 1 до 500; по умолчанию 500 |

Результат содержит `totalCount`, `processedCount`, `count`, `nextOffset`, `truncated`, `elements` и `diagnostics`.
Порядок определяется ID. Продолжайте с полученным `nextOffset`.
При явном списке отсутствующие ID и элементы другой категории также занимают позицию страницы.
Если модель изменилась, проверьте документ и начните чтение страниц заново.
Размер ответа ограничен примерно 1 МБ.
Если первая строка страницы превышает бюджет, вместо неё возвращается `RowExceedsBudget` с продвижением смещения.

Для прямой возвращаются её концы. Для дуги дополнительно возвращаются средняя точка, центр, радиус и нормаль.
У точечной колонны возвращается точка вставки. Инструмент не подменяет ось углами габаритного параллелепипеда.
`axisIsExact=false` и `canReconstruct=false` запрещают считать такую точку измеренной осью.
Для точечной колонны блок `columnConstraints` содержит фактические ID нижнего и верхнего уровней, их `ProjectElevation`, смещения и вычисленные отметки.
Эти отметки выведены из ограничений. Они не являются измерением геометрии и не превращают точку в ось.
Ошибка чтения ограничений возвращается диагностикой. Она не удаляет доступную точку вставки из ответа.
`canReconstruct=true` означает достаточность геометрических данных. Это не обещание поддержки дуги инструментом создания.

Список числовых параметров типа ограничен. Для каждого значения указывается тип данных.
Признак `truncated` внутри `typeParameters` сообщает о неполном списке.

## Создание

`author_structural_members` принимает `membersJson`, `dryRun=true` и `pin=false`.
`membersJson` содержит массив от 1 до 100 описаний. Максимальный размер JSON — 1 МиБ, глубина — 16.
Повторяющиеся ключи JSON отклоняются MCP-обёрткой.
Проверка внутри плагина дополнительно ограничивает весь запрос 256 Ки символов.
Каждая карта параметров содержит не более 32 значений. Текстовое значение ограничено 1024 символами.

Каждое описание содержит:

- уникальный непустой `sourceId` для сопоставления ответа с исходным заданием;
- `role`: `beam` или `column`;
- `family`, `baseType`, `typeName`;
- `p0_ft` и `p1_ft`: по три конечных числовых значения;
- необязательные `typeParams`, `instanceParams` и `levelName`.

Семейство и базовый тип должны быть загружены в проект.
Существующий тип не изменяется. Новый тип создаётся копированием базового типа внутри проекта.
`Document.EditFamily` и сохранение RFA не используются.
Неоднозначные имена параметров, несовместимые значения и конфликтующие размеры вызывают отказ.
Наклонные колонны и неподдерживаемая геометрия отклоняются.
Закрепление экземпляров выполняется только при `pin=true`.

Сначала выполните `dryRun=true`. Предварительная проверка не создаёт элементы.
Она не гарантирует, что Revit примет геометрию при реальном размещении.
После проверки выполните `dryRun=false` в том же подтверждённом документе.
При выключенном автовыполнении Cortex запрашивает обычное разовое подтверждение.
Режим «только чтение» и отключение отдельного инструмента продолжают действовать.

Ответ балки содержит `placementVerified=true` после проверки фактических концов `LocationCurve`.
Ответ колонны содержит `constraintsVerified=true`, `placementVerified=false` и `physicalZVerified=false`.
Для колонны проверяются XY, тип, уровни и смещения. Физические отметки низа и верха независимо не измерены.
Фактические ограничения возвращаются в `columnConstraints`. Не трактуйте их как измеренную геометрию.

Выбор уровней использует `ProjectElevation`. Предположение об ошибке из-за перемещения базовой точки проекта не подтверждено.
`LocationPoint.Z` не используется как универсальная проверка низа колонны.
Явный уровень с отрицательным смещением сам по себе не запрещён.
Неоднозначное имя уровня отклоняется в предварительной проверке с понятным сообщением.

## Ошибки и откат

Пакет создания выполняется целиком. Ошибка одного элемента отменяет весь пакет.
Транзакция получает `IFailuresPreprocessor` и `SetClearAfterRollback(true)` до изменений.
Для этого инструмента предупреждения также требуют отката.
Ответ сохраняет примитивные описания сбоев, важность и ID затронутых элементов.

Проверка результата выполняется до завершения группы транзакций.
После подтверждённого отката ответ не представляет отменённые ID как созданные элементы.
Если откат не подтверждён, ответ явно сообщает неопределённое состояние.
Сетевой таймаут не прерывает код Revit. Проверьте модель перед повтором запроса.
После таймаута группа может откатиться даже после успешного `Commit` вложенной транзакции.
Поэтому состояние модели после таймаута может содержать изменения или не содержать их.
`sourceId` не обеспечивает устранение повторного создания между отдельными вызовами.

## Проверка в Revit

Используйте отдельный тестовый проект и небольшой пакет.

1. Создайте одну балку и одну вертикальную колонну. Проверьте типы, размеры, оси и уровни.
2. Убедитесь, что один шаг отмены удаляет весь пакет вместе с новыми типами.
3. Вызовите ошибку параметра второго элемента. Убедитесь, что первый элемент и новые типы отсутствуют.
4. Проверьте откат при предупреждении Revit и наличие диагностики в ответе.
5. Запросите конфликт размеров существующего типа. Проверьте сохранность исходного типа.
6. Запросите наклонную колонну. Убедитесь в отказе до изменений.
7. Проверьте предварительную проверку, ручной отказ и режим «только чтение».
8. Прочитайте прямую, дугу и точечную колонну. Проверьте единицы и признаки геометрии.
9. Повторите чтение через второй порт. Убедитесь, что документы и результаты не смешиваются.
10. Проверьте колонну при базовой точке проекта Z=0 и Z=+1000 мм, ненулевых смещениях и другой Elevation Base.
11. Сравните фактический низ и верх, `LocationPoint.Z`, начало преобразования экземпляра и ограничения. Не принимайте вычисленные отметки за геометрическую проверку.
12. Проверьте колонну, низ которой выше исходного верха по умолчанию. Порядок записи ограничений требует отдельной нативной проверки.

Компиляция и обычные тесты не заменяют эти проверки внутри Revit.

## Исправления ревью: сборка .17

4 ноября 2026 года исправлены подтверждённые замечания [ревью PR №5](https://github.com/AlexFspb/RevitCortex/pull/5#issuecomment-6601207584):

- Ответ колонны различает проверку ограничений и независимую проверку физической высоты.
- Оба инструмента возвращают фактические ограничения колонны как отдельные производные данные.
- Регенерация в цикле вызывается после создания или активации типа. Финальная регенерация сохранена.
- Неоднозначные имена уровней возвращают ошибку ввода. Сопоставление базовых типов не учитывает регистр.
- Целые числа вне диапазона Int64 отклоняются как ошибка ввода до преобразования в double.
- Слишком большая первая строка не останавливает продвижение страницы.
- В описаниях команд добавлены подсказки перевода ft ↔ mm.

Гипотеза о неверной отметке из-за перемещения базовой точки не считается доказанной.
Семантика `ProjectElevation` сохранена согласно [справочнику Autodesk](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/895ef506-bfea-cc4e-31f8-aad2af6672e4.htm).
Проверка физической высоты и изменение порядка записи ограничений остаются нативными сценариями из списка выше.

Проверка `.17`: 992 теста успешно, 1 пропущен, ошибок нет.
Plugin и Tools собраны для Debug R26 и Release R26. Сервер собран для Release.
Каталог MCP проверен для четырёх портов: 301 инструмент. Команды в Revit не отправлялись.
