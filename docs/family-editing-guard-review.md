## Запрос пользователя

Недостаточно рекомендовать агенту правильный режим.
Cortex должен программно запрещать запуск при открытой транзакции и неправильный вызов `EditFamily`.
Проверки не должны закрывать чужую транзакцию или отключать подтверждения.

## Реализованные уровни

### 1. Проверка входа

`ScriptFamilyEditGuard.CheckStart` проверяет существование документа и `IsModifiable`.
При открытой транзакции запуск отклоняется во всех трёх режимах: `auto`, `group`, `none`.
При `IsReadOnly=true` режимы `auto`/`group` отклоняются. Обычное чтение через `none` остаётся возможным.

В `SendCodeToRevitTool` проверка выполняется до подтверждения и повторяется после него.
Повторная проверка нужна, поскольку модальное подтверждение обрабатывает события интерфейса.
В `RoslynExecutor` проверка выполняется ещё раз до компиляции и создания собственной транзакции.
Код проверки не вызывает `Commit`, `RollBack`, `Close` или автоматический повтор.

### 2. Проверка компилятора

`FamilyEditCallRewriter` использует семантическую модель Roslyn.
Он распознаёт метод `Autodesk.Revit.DB.Document.EditFamily`, а не произвольное совпадение текста.
Комментарии, строковые литералы и `nameof` не блокируют обычные скрипты.

В `auto`/`group` распознанный вызов отклоняется до исполнения кода и создания транзакции исполнителя.
Эта проверка компилятора выполняется после штатного подтверждения Cortex.
Захват метода в делегат и условный вызов `doc?.EditFamily(...)` отклоняются вместо необработанного обхода проверки.
Агент получает рекомендацию использовать прямой вызов.

### 3. Проверка непосредственно перед API

В режиме `none` компилятор заменяет прямой вызов на `ScriptFamilyEditGuard.EditFamily(document, family)`.
Выражения документа и семейства вычисляются один раз, в прежнем порядке.
Поддержаны именованный аргумент `loadedFamily`, экранированное имя метода, локальные функции и лямбда-выражения.

Обработчик заново проверяет:

- существование документа;
- отсутствие открытой транзакции;
- возможность записи;
- существование семейства;
- принадлежность семейства документу через `Document.Equals`;
- `IsEditable` и `IsInPlace`.

Поэтому транзакция, открытая уже внутри скрипта, блокирует последующий вызов API.
Остальные нативные ограничения продолжает проверять Revit.

## Ответ агенту

Добавлен код `ScriptPreconditionFailed = 410`.
`ScriptPreconditionException` формирует структурированный ответ без ссылки на отказ пользователя.

| Поле | Отказ перед скриптом | Отказ перед API внутри скрипта |
|---|---|---|
| `scriptExecuted` | `false` | `true` |
| `phase` | `before_script` | `before_api_call` |
| `externalEffectsMayRemain` | `false` | `true` |
| `transactionState` | `not_started_by_cortex` | `not_managed` |

`reason` указывает причину, например `OpenTransaction`, `ReadOnlyDocument`, `FamilyDocumentMismatch`.
`blockedOperation` указывает `script_start` или `Document.EditFamily`.
Ошибки компиляционной политики используют `FamilyEditCallRejected`; сообщение содержит строку и причину.
Смещение строк исправлено с 12 на 9 по фактической обёртке `WrapCode`.

При отказе до запуска Cortex не меняет уже открытую транзакцию.
При отказе внутри скрипта ранее выполненные действия могут сохраниться.
Скрипт обязан самостоятельно освободить свои транзакции и документы.

## Ограничения

- Это не полная изоляция произвольного C# и не доказательство безопасности скрипта.
- Вызовы внутри уже скомпилированных библиотек не переписываются.
- Не перехватываются все методы Revit, нативные падения или все модальные окна.
- Проверка `IsModifiable` не является проверкой всех открытых групп транзакций.
- Динамическое обновление и уже редактируемое семейство остаются нативными проверками API.
- Чтение в `none` при уже открытой транзакции теперь тоже отклоняется. Это намеренное ужесточение границы запуска.
- Если сам скрипт перехватывает исключение проверки, дальнейшее выполнение определяется его кодом. Запрещённый API-вызов всё равно не происходит.
- Специализированный инструмент изменения параметров семейства и общий откат нескольких документов не добавлены.

Существующие запреты sandbox, аудит, режим «только чтение», порты и трёхсекундные подтверждения сохранены.
Совместимое поведение предупреждений сохранено. Добавлен явно выбираемый строгий режим для собственных транзакций скрипта.

## Учтённый отчёт Claude

Отчёт о guidance.4 подтвердил, что C#-обёртка не допускает объявления классов в теле скрипта.
В guard.5 добавлены готовые средства:

- `FamilyLoadPolicy : IFamilyLoadOptions` с обязательными `overwriteParameterValues` и `useProjectSharedFamilies`;
- `ScriptFailureHandling.Configure(tx, rollbackOnWarnings: true)` для отката при предупреждениях и ошибках.

Политика загрузки продолжает конфликт загрузки с двумя явно выбранными настройками.
Она не принимает ошибки модели и не заменяет подтверждение Cortex.
Вызов `Configure(tx)` без второго аргумента сохраняет прежнее поведение.
Строгий режим записывает предупреждения и запрашивает откат, не удаляя их как принятые.
Локальный отчёт различает `rollback_requested` и `warnings_removed`.

Исправлены описания и руководство:

1. В `none/group` скрипт сам возвращает `Failures`, `OmittedFailures` и `DiagnosticReportPath`.
2. `SaveAs` получает строковый путь в существующую папку; проверка файлов и резервной копии выполняется вне sandbox.
3. Без разрешённой перезаписи используется `OverwriteExistingFile=false`.
4. Проверяется `bool`, который возвращает `Close(false)`, а не только исключение.
5. Правило завершения всех групп отделено от условия `LoadFamily`, связанного с изменяемостью целевого документа.
6. Историческая спецификация 2026-05-29 получила отметку об устаревшей формулировке.

Русский язык operator_11 сохранён по пользовательскому предпочтению. Копия совпадает с основным руководством.
