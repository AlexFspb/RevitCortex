## Состав изменения

- Core: небольшой реестр поставщиков, контракт API 1, профиль схем JSON и учёт одной операции.
- Session: случайный токен текущего контекста документа, доступный без обращения к UI.
- Plugin: асинхронный приём в существующий ExternalEvent и маршрутизация пяти инструментов.
- Server: пять MCP-обёрток; отдельные соединения управления без ожидания общего мьютекса.
- Аудит: приём, фактический вызов и завершение с ID/контекстом/версиями; без полных аргументов.
- Пример: отдельный тестовый поставщик с чтением и обратимой записью Project Number.
- Документация: регистрация, перегрузка модуля, установка, ограничения и сценарии нативной проверки.

Новый транспорт, новый порт, очередь множества заданий и расчётные формулы не добавлялись.
Один слот Cortex обслуживает обычные инструменты и команды поставщиков.
Регистрация `mep-calculations` и общие команды UI/адаптера остаются задачей MEP.

## Что проверить при обзоре кода

1. При повторе UUID не выполняется повторная запись. Конфликт аргументов даёт явный отказ.
2. Истёкшая/отменённая команда не запускается при поздней обработке события.
3. Смена документа и разрешений проверяется перед фактическим вызовом, включая выход из подтверждения.
4. Статус/отмена не используют Revit API и не ждут UI или обычную долгую команду MCP.
5. Нет внешней транзакции Cortex поверх транзакций поставщика.
6. Ошибка ответа не выдаёт ложный откат ранее зафиксированных изменений.
7. При ошибке загрузчика прежний обработчик не остаётся доступным; поколение меняется.
8. Завершение публикуется после освобождения блокировки поставщика. Ошибка очистки не скрывается.
9. После завершения освобождаются аргументы и обработчики отмены; история результатов ограничена.
10. Скрипты C# не могут обращаться к реестру/службе команд для обхода ограничений.

## Что ещё не подтверждено в Revit

Новая сборка **не установлена**. Работающий Revit и пользовательские конфигурации не изменялись.
Нет разрешения считать текущую рабочую модель тестовым документом.
Нативные T02/T04/T05/T08/T10/T11 необходимо выполнить после установки на отдельном тестовом проекте.
T12/T14 требуют адаптера со стабильным загрузчиком; демонстрация не заявляет поддержку горячей перезагрузки.
Совместный сценарий расчёта MEP проверяется после подключения его адаптера.

API 1 принимает доверенные установленные поставщики. Он не изолирует произвольную DLL.
Поставщик обязан честно объявлять эффекты и соблюдать собственные транзакции/обработку сбоев.
Read-only проверяется по декларации операции; Cortex не перехватывает каждое внутреннее обращение сторонней DLL.
При native crash операция может не вернуть ответ. После перезапуска требуется проверка модели.
Эти ограничения нельзя скрывать за успешными модульными тестами.
